# SDK restoration and three prime situations — Linux

FOU-148, draft 56b. Contract: [PRD §17.2](../../prd.md#172-launch-gates-not-yet-passed), SDK fallback's additional restoration/channel/priming requirement, and §5.5. No product code or commit-tier tests changed.

## Verdict

**Supported on the tested Linux implementation.** Two retained disposable actual daemon → detached Worker Host → pinned Pi **SDK** worker runs reopened the same on-disk conversation after worker exit, without replaying its completed tool execution. Fresh, recovery and manual in-place compaction primes were observed in actual model history, not inferred from unit tests or generated by the probe. The final driver additionally checks identical full prime bodies except for the situation header, source/hash records and acknowledgements.

This is **not full SDK launcher qualification**. Other §17.2 gates, macOS, daemon-kill survival/reconnect, automatic or mid-tool-round compaction, and execution resumption are not claimed. The known shared extension redial failure remains unchanged: SDK selection did not repair it. Do not use this record as passing reconnect evidence or as a claim about SDK capability beyond this implementation.

## Observation-tool and environment errors, not SDK failures

Three preliminary attempts stopped before meaningful gate evidence and cleaned their owned resources:

1. [`yaml-key.json`](sdk-restore-and-prime/observation-errors/yaml-key.json): driver placed factory instructions at the YAML root. Validator correctly rejected the unknown key. Corrected the fixture to `defaults.instructions` and explicitly set its disposable worktree root.
2. [`wrong-observer-event.json`](sdk-restore-and-prime/observation-errors/wrong-observer-event.json): observer expected Pi's `input` event, but Foundry delivers a custom message. The actual channel delivered/acknowledged the work; the faux script failed to recognize it and emitted an empty-command answer rather than its side effect. Corrected only the observer to use `before_agent_start`'s actual custom message. No product fix or synthetic input was added.
3. [`tmp-inodes.json`](sdk-restore-and-prime/observation-errors/tmp-inodes.json): Git fixture initialization failed `ENOSPC`. `df -h /tmp` showed 22 GiB available but `df -i /tmp` showed only 151 free inodes out of 1,048,576, later zero. Switched **only owned runs** to a private directory under `/home/mark`; no unrelated cleanup. Both subsequent SDK probes completed with empty marked-process inventories after shutdown.

No reproducible product failure was observed, so no product remediation was implemented. The driver's historical `requires-classification` status on failed attempts is deliberately superseded only by these explicitly classified tool/environment observations, not interpreted as a failed SDK capability.
